Package review · CGDtheme · July 10, 2026

The theme works for the README's happy path — and fails quietly almost everywhere else

I installed the package, rendered 23 test charts (the README examples plus stress tests it never tries), ran a palette validator on every CGD palette, and audited each exported function. The concept is sound and simple charts look genuinely on-brand. But the package has 5 critical issues that produce broken or misleading charts, measured accessibility failures in its palettes, and an architecture that silently takes over the whole R session with no way back.

Every README example rendered, then stress tests the README never exercises: facets, subtitles and captions, negative values, horizontal bars, date axes, area charts, histograms, 10-category scatters, and set_theme() / theme_minimal() interaction. Critical — broken or misleading charts

These produce output a reader can't decode, or code that errors — the kind of thing that reaches a publication before anyone notices.

F1

Legends are globally suppressed — colored charts become undecodable by default

critical

set_theme() hardcodes legend.position = "none". Any chart that maps color and doesn't remember to call add_legend() ships with no key at all. Below, the README's own scatter example: the reader has no way to know what the colors mean — there isn't even a colorbar.

Fix: default legends on (bottom or right) and hide them explicitly only in helpers that add direct labels. A brand theme should make the safe thing automatic, not opt-in.

F2

add_labels(column, "line") ignores its first argument — works only if the column is literally named label

critical

For line charts the helper builds aes(label = label) internally, so it always looks for a data column named label. The argument you pass is a decoy. Renaming the column to anything else errors:

ggplot(df, aes(year, len, group = supp)) + geom_line(aes(color = supp)) +
  add_labels(lbl, "line")
#> Error: object 'lbl' not found

The README example only works by coincidence — its tutorial happens to name the column label. The bar variant has the inverse problem: it takes a detached vector (sample_df$len), which silently mislabels bars if the data is reordered, filtered, or faceted.

Fix: accept a column name via tidy evaluation (add_labels(lbl, "line") → aes(label = {{ label }})) for both variants, and document that it must be a column, not a vector.

F3

More than 8 categories silently assigns identical colors to different categories

critical

The default discrete scale recycles the 8-color palette. With 10 categories, a and i are the same teal; b and j the same gold — the legend asserts a distinction the chart doesn't make. The only signal is a console warning nobody sees in R Markdown.

Fix: beyond 8, fail loudly or fall back to a labeled gray for the tail — and the guidance should say "fold small categories into Other," which is what the style guide intends anyway.

F4

Sofia Pro is hardcoded in 7 places, never registered, and silently substituted

critical

This machine has no Sofia Pro installed. All 23 charts rendered with zero warnings — a fallback face stood in everywhere, and nothing tells the user their output is off-brand. The README never mentions the font requirement. Worse, the code asks for style-baked family names like "Sofia Pro Light Italic" and "Sofia Pro Bold", which font matching frequently fails to resolve even when Sofia Pro is installed (the family is "Sofia Pro"; light/italic/bold are weights and styles).

Fix: register faces at load with systemfonts::register_font() using family + weight/style, warn once when the font is missing, name the fallback deliberately, and document installation in the README.

F5

setup_plot() takes over the R session permanently — no reset exists

critical

One call mutates global state four ways: theme_set(), 12 update_geom_defaults() calls, and 4 options(). After that, even a user who explicitly asks for theme_minimal() still gets CGD colors and geom sizes — and no reset/unset function is exported. The only way out is restarting R. This is hostile to R Markdown documents, Shiny apps, and any script that makes non-CGD plots too.

Fix: restructure to the standard compositional pattern — theme_cgd() + scale_colour_cgd()/scale_fill_cgd() added per-plot — and keep setup_plot() as an opt-in convenience that snapshots prior state and gets a paired reset_plot().

High — measured color & styling failures

Checked with a palette validator (lightness band, chroma floor, CVD separation, contrast) — these are numbers, not taste.

F6

Five of eight categorical colors fail 3:1 contrast against white

high

Measured contrast vs. a white surface: light_gold 1.17:1, light_gray 1.29:1, light_blue 1.39:1, gold 1.72:1, teal_gray 2.56:1. The light fills are nearly invisible as bars and genuinely invisible as scatter points. The palette also orders two of the palest colors adjacently (positions 4–5), so neighboring series blur together.

Fix: reorder so dark, saturated colors come first; either deepen the pale tints to clear 3:1 or reserve them for large filled areas with outlines, never for points or thin marks.

F7

The default continuous gradient (teal → gold) passes through muddy gray-olive

high

setup_plot() wires continuous color to a two-hue interpolation from light_teal to gold. Mid-range values desaturate into an ambiguous olive that reads as "no data" — visible in the scatter under F1. The package ships proper single-hue sequential ramps (sequential3, sequential4) but never connects them to the continuous scale.

Fix: use a sequential ramp (light → dark teal) for continuous scales; keep teal/gold as a diverging pair with a neutral midpoint for signed data.

F8

Stacked-bar labels use fixed dark text — unreadable on dark segments

high

add_labels(…, "stacked") always renders near-black text. On the dark teal segments the labels are low-contrast; there's no contrast-aware flip to white.

Fix: compute label color from segment luminance (white on dark fills, ink on light fills).

F9

add_labels(…, "bar") breaks on negative values and clips at the panel top

high

The fixed vjust = -0.5 assumes bars grow upward. Negative bars get their labels inside the bar (dark on dark teal), and the tallest bar's label collides with the panel edge unless the user remembers the README's manual expansion() incantation.

Fix: set vjust by sign of the value, and build the headroom expansion into the helper (or theme) instead of the README.

F10

Facets are broken: panels fuse together and strips are unbranded

high

The theme sets panel.spacing = 0, so faceted panels share edges and their axis labels collide, while strip.background/strip.text fall through to ggplot's gray defaults — the one part of the chart that isn't branded at all. Faceting is bread-and-butter for policy charts; the theme has clearly never been run against one.

Fix: panel.spacing = unit(1, "lines") and style strip.text/strip.background in the brand fonts and colors.

F11

Subtitles and captions render completely unstyled

high

plot.subtitle and plot.caption aren't defined in the theme, so they fall back to plain defaults — wrong face, wrong color, cramped against the title. Nearly every published CGD chart needs a source note; the caption is arguably the most important element the theme forgot.

Fix: style plot.subtitle (deck text under the title) and plot.caption (small, muted, left-aligned source line), plus plot.caption.position = "plot".

F12

Geom coverage is patchy: area charts render near-black, boxplot whisker caps stay black

high

setup_plot() styles 12 geoms but misses area, ribbon, errorbar, segment, and tile. An area chart comes out charcoal; the README's own boxplot recipe (stat_boxplot(geom = "errorbar")) draws black whisker caps on teal boxes.

Fix: extend geom defaults to the missing geoms; add a visual regression test that renders one chart per supported geom.

F13

set_theme() used on its own produces a half-branded chart

high

The theme and the color scales live in different mechanisms (theme object vs. session options), so + set_theme() — the obvious per-plot usage — gives brand chrome with stock ggplot red/green/blue, and hides the legend on top of it (F1). Users can't tell which layer of the system they're missing.

Fix: falls out of the F5 restructure — per-plot theme and scale functions that compose.

Medium — API design & robustness

Paper cuts and future breakage. None ruins a chart today; several will bite on the next ggplot2 release or the first user who deviates from the README.

F14

No scale_fill_cgd() / scale_colour_cgd() exported

med

The palettes (sequential, polar, stoplight) exist but are reachable only through the global session options or manual scale_fill_manual(values = cgd_palette(...)). There's no per-plot, palette-picking scale function — the single most common thing users of a brand package reach for.

F15

Deprecated ggplot2 APIs will break on a future release

med

Every fresh session's first discrete-color plot emits a user-facing warning: The `scale_name` argument of `discrete_scale()` is deprecated as of ggplot2 3.5.0. The line-oriented size argument (deprecated since 3.4.0) is still used in add_separator_line(), add_annotations(), and the step/path geom defaults.

F16

Loose argument handling: silent no-ops and missing defaults

med

add_legend() errors because neither argument has a default (the README implies sensible ones exist). add_separator_line("diagonal", 5) prints "Please check the parameters used." and silently adds nothing. add_grid_lines() with no arguments is a silent no-op. add_labels() and add_annotations() accept any string and return NULL on typos.

Fix: defaults (position = "bottom"), match.arg() on every string parameter, and errors — not print() — on bad input.

F17

wrap_axis_text(): dead argument, inverted naming, x-axis only

med

The column argument is documented as deprecated but still required-looking in the README. add_space = TRUE confusingly means "the labels lack spaces, so insert them." And it only returns an x scale — nothing helps the horizontal bar chart, which is where long labels actually live (they wrap fine on y with plain str_wrap, but the helper can't do it).

F18

The theme claims complete = TRUE without defining base elements

med

set_theme() marks itself a complete theme but never sets text, line, rect, or title. Everything not explicitly listed (strips, subtitle, caption, legend keys…) silently falls through to ggplot's built-in defaults — which is exactly how F10 and F11 happened, and why the next forgotten element will fail the same quiet way.

Fix: build on a real base — theme_minimal(base_family = …) %+replace% theme(…) — so unlisted elements inherit brand text/line settings instead of stock ones.

F19

Palette details: stoplight gold fails contrast; sequential ramps break hue and lightness order

med

Good news first: the stoplight's red/green pair is actually colorblind-safe (the green is teal-leaning; worst-case separation ΔE 48). But gold fails contrast (1.72:1) in every palette it appears in, and the sequential ramps aren't clean: sequential2/3 hop hues (blue → teal), and sequential4 ends in dark_gray — a gray as the "darkest teal," which misreads as a different category rather than "more."

F20

change_boxplot_color() is a wrapper, not a layer — and duplicates fill scales

med

It's the only helper that takes the whole plot as an argument instead of composing with +, and it adds a scale_fill_manual() that collides (with a user-facing message) if any fill scale exists. The outline/fill pairing also only aligns by luck of both scales sharing palette order.

Fix: replace with a proper scale_fill_cgd(lighten = 0.5) variant so it composes like everything else.

F21

Packaging hygiene: no tests, undeclared dependency, README installation bugs

med

There is no test suite of any kind. The README's first instruction, install.packages(devtools), errors as written (missing quotes) — then the next line uses remotes:: instead of the devtools it just installed. README examples use %>%, filter(), and mutate() without ever loading dplyr, which isn't in Imports or Suggests. DESCRIPTION still carries the consultant's personal email as maintainer and version 0.0.0.9000.

Fix: testthat + vdiffr snapshot tests per chart type, a README that runs top-to-bottom in a fresh session, and CGD as maintainer.

What's genuinely good

Worth keeping through any refactor.

  • The single-color defaults are right: one-series bars, lines, and scatters come out clean and recognizably CGD with zero effort — that's the 80% case done well.
  • Direct end-of-line labeling via ggrepel (multi-line chart) follows dataviz best practice — better than a legend when it works.
  • The projection / separator / trend-line combo maps well to how CGD actually annotates time series.
  • Colors and palettes were recently centralized into one internal source of truth — the right foundation for the palette fixes above.
  • The stoplight palette is accidentally colorblind-safe — keep that green.
